# MAINTAIN AI — Local Intelligence Engine

A local-first AI inference and model-serving application for the MAINTAIN AI industrial ecosystem.

## What this build does

This project runs selected MAINTAIN AI intelligence workloads locally on a Windows PC or industrial edge computer and exposes them through a local REST API bound to `127.0.0.1` by default.

Initial capabilities:
- TimeRadar zero-shot anomaly detection adapter
- Chronos-2 forecasting adapter
- Timer forecasting adapter
- MAINTAIN AI online anomaly/degradation services
- Existing Random Forest baseline
- Model and API health/status
- Structured inference responses
- Windows desktop application
- Windows installer generated by GitHub Actions

## No model training is required

The local engine is an inference/runtime layer. It does **not** train the models during installation.

The lightweight services work with the base installation. Heavy pretrained model runtimes/checkpoints are optional and are loaded only when their dependencies and local model files are available.

This keeps the normal desktop installer much smaller and suitable for an 8 GB RAM laptop. Large model weights should not be committed to this repository or bundled into the base installer.

## Local API

When the desktop engine is running:
- Health: `http://127.0.0.1:8000/api/health`
- Model manager: `http://127.0.0.1:8000/api/model-manager`
- Interactive API documentation: `http://127.0.0.1:8000/docs`
- Inference routes: `/api/inference/online`, `/baseline`, `/timeradar`, `/chronos2`, `/timer`

The engine is intentionally bound to localhost rather than exposed to the public internet by default.

## Model boundary

An anomaly score is not automatically a machine-failure probability. Forecast models forecast signal values; they do not automatically produce calibrated failure probabilities.

The calibrated MAINTAIN AI 24h/48h/7d/30d risk model remains a separate milestone until validated with sufficient industrial data.

## Build outputs

GitHub Actions produces two Windows artifacts when the test and packaging stages pass:
1. `MAINTAIN-AI-Local-Intelligence.exe` — packaged desktop executable.
2. `MAINTAIN-AI-Local-Intelligence-Setup.exe` — Windows installer.

The installer includes the application and project documentation. Heavy ML runtimes and model checkpoints remain optional rather than being silently downloaded into the installer.

## Development model setup

For a source checkout, `scripts/install_models.py` can prepare optional model dependencies/checkpoints. A packaged installation should use the documented model-management workflow rather than assuming a Python interpreter is installed system-wide.
